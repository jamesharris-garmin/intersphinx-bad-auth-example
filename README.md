# Welcome!

This is a demo project that uses docker-compose to demonstrate a credential
leak in the sphinx.ext.intersphinx documentation.

It uses a build of the readthedocs-examples/example-sphinx-basic as a remote
project. It hosts the intersphinx remote in a docker image using caddy and a
simple basic_auth from the examples.

## What is the issue?

Under certain circumstances intersphinx can leak credentials into the logs when
they should not be leaked.

Presented in this repository are two example cases that demonstrate the issue
and one control case.

### Test Requirements

The following programs must be installed and in the path in order to execute
these tests conveniently.

* `docker` with the `compose` plugin (either docker engine or docker desktop will work for this example)
    * [Docker CE instructions](https://docs.docker.com/engine/install/#installation-procedures-for-supported-platforms)
    * [Docker Desktop](https://docs.docker.com/get-started/get-docker/)
* `uv`
    * [uv install instructions](https://docs.astral.sh/uv/#installation)

### Common Assumptions

The remote server is running at `http://localhost:7999` and uses the dummy credentials:

* Username: `Bob`
* Password: `hiccup`

The remote server is provided by docker and automatically started by the nox
configuration.

### Case 1: Incorrect basic auth credentials in URL:

This case uses the URL: `http://Bob:badpasswd@localhost:7999` which uses a
password that does not match the basic auth password.

To execute this case run:

```shell
uv run nox -s "docs(test_case='bad_password')"
```

This will fail to run the logs and print:

```
WARNING: failed to reach any of the inventories with the following issues:
intersphinx inventory 'http://Bob:badpasswd@localhost:7999/objects.inv' not fetchable due to <class 'requests.exceptions.HTTPError'>: 401 Client Error: Unauthorized for url: http://Bob:badpasswd@localhost:7999/objects.inv
```

Note that the incorrect credential `badpasswd` appears in the WARNING logs when
it should be censored.

### Case 2: Correct credentials Non-existent path

This case uses the url: `http://Bob:hiccup@localhost:7999/doesnotexist` to
attempt to access a sphinx instance in the wrong location on the server.

This could be caused by the user using the correct credentials but mystyping
the the path to the remote sphinx documentation used by intersphinx.

To execute this case run:

```shell
uv run nox -s "docs(test_case='good_password_bad_path')"
```

This will fail to run the logs and print:

```
WARNING: failed to reach any of the inventories with the following issues:
intersphinx inventory 'http://Bob:hiccup@localhost:7999/doesnotexist/objects.inv' not fetchable due to <class 'requests.exceptions.HTTPError'>: 404 Client Error: Not Found for url: http://Bob:hiccup@localhost:7999/doesnotexist/objects.inv WARNING: failed to reach any of the inventories with the following issues:
```

Note that the correct credential `hiccup` appears in the WARNING logs when
it should be censored.


### Control case:

This case assumes we are using the correct credentials and the correct path.


To execute this case run:
```shell
uv run nox -s "docs(test_case='happy_path')"
```

Running this case should result in the documentation being generated by sphinx as expected.
